## v0.28.0 — 2026-08-10

- **멀티 라이터 감사 후속 — 강제층이 소리 없이 통과하던 세 상태를 닫았습니다** (ADR 0041):
  ① 게이트 이미터·verify 매퍼가 변경 파일 범위 해석에 실패하면 이제 stdout `scope: FAILED`
  마커와 함께 비영(exit≠0)으로 종료합니다 — 이전에는 빈 출력 + exit 0이라 CI 잡 전체가
  아무것도 검사하지 않고 초록이었습니다. ② main 푸시 CI는 `--all`(전체 트리 감사)로 돕니다:
  각각 초록인 두 PR이 병합으로 만든 조합 상태(예: 한쪽이 그룹 제거, 다른 쪽이 그 그룹의
  파일 추가)를 이제 매 푸시마다 잡습니다. ③ CI에 시크릿 스캔 백스톱이 생겼습니다 —
  `.githooks/pre-push` 스크립트 그대로를 이 런의 범위로 구동하므로(패턴 복제 없음),
  `core.hooksPath` 배선을 안 한 클론의 커밋도 머지 전에 스캔됩니다.
- **스캐폴드 리프레시 안내가 방향을 압니다** (ADR 0042): `/ywr-harness:harness-init`가 성공한
  실행마다 레포 루트에 `.harness-version`(이 레포를 마지막으로 스캐폴드한 플러그인 버전)을
  기록하고, 드리프트 발견 시 안내 훅이 이를 읽어 조언의 방향을 정합니다 — 레포가 내 설치본보다
  새로우면(다른 멤버가 신버전으로 리프레시) "init 금지, 플러그인 업데이트"로 뒤집고, 오래됐으면
  리프레시를 측정된 방향으로 권하며, 같은 버전이면 핸드에딧으로 명명합니다. 스탬프가 없으면
  기존 방향맹 경고가 이제 **사람용 배너에도** 나옵니다(이전에는 모델용 컨텍스트에만 있었습니다).
- **init.ps1이 맹목적 다운그레이드를 거부합니다** (ADR 0042): 레포 스탬프가 실행 중인 플러그인
  버전보다 새로우면 아무것도 쓰지 않고 거부합니다(의도된 롤백은 `-Force`). **기존 스캐폴드
  레포 조치 1건**: 다음 리프레시 후 `.harness.json`의 groups에 `^\\.harness-version$` 클레임
  한 줄을 추가하세요 — 없으면 CI가 미클레임 파일로 한 번 크게 실패합니다(신규 레포의 기본
  선언에는 포함됨).

- 핸드오프 선언이 **작업 라인별 디렉터리 형태**를 지원합니다 (ADR 0040): `.harness.json`의
  `handoff` 값이 `/`로 끝나면 디렉터리 선언입니다 — 작업 라인마다 재개 파일 하나를 두는
  멀티 라이터 레포용 형태로, 파일 이름은 사람이 아니라 작업 라인을 따릅니다. 게이트 이미터가
  `handoff:` 줄에 디렉터리 형태임을 표기하며, 단일 파일 선언은 기존과 동일하게 동작합니다.
- 핸드오프는 **장부가 아니라 재개 지점**입니다: 슬라이스 마감(`/ywr-harness:slice-close`)이
  대체된 Current state 섹션을 `docs/handoff-archive/<같은 파일명>`으로 옮기도록 안내합니다.
  히스토리는 git 체크포인트 커밋에 이미 있으므로, 매 세션 다시 읽는 재개 파일은 얇게
  유지합니다.

## v0.26.0 — 2026-08-07

- 스캐폴드 리프레시 안내 훅이 **낡은 세션(stale session)을 감지합니다** (ADR 0039): 플러그인이
  세션 도중 업데이트되면 실행 중 세션은 `/reload-plugins` 또는 재시작 전까지 이전 버전의 훅을
  계속 실행합니다(플랫폼 동작, 문서 검증). 이 상태에서 기존 안내를 따르면 harness-init 이
  구버전 템플릿을 배치해 **정상 갱신된 레포를 되돌릴 수 있었습니다**(v0.23.2 훅이 v0.25.0
  레포에 리프레시를 권한 실측 사례). 이제 드리프트를 발견하면 훅이 자기 사본이 등록된
  설치본인지 확인하고, 아니면 실행 중 버전과 등록된 버전을 명시하며 `/reload-plugins`(또는
  재시작)를 안내하고 이 세션에서의 harness-init 실행을 금지합니다.
- 확인이 실패하면(레지스트리 없음·파싱 불가·비캐시 사본 등) 기존 안내가 그대로 나옵니다 —
  이 감지는 조언을 고칠 수만 있고 훅을 침묵시키지 않습니다. 등록된 버전이 실행 중 버전과
  같으면(같은 버전의 재등록 — 템플릿이 같아 뒤집힐 것이 없음) 역시 기존 안내를 유지합니다.
  `--plugin-dir` 개발 사본은 기존 방향맹(direction-blind) 주의 문구 그대로입니다.

## v0.24.0 — 2026-08-07

- 리뷰 티어에 **파생 사본 면제** 추가 (ADR 0037): `.harness.json`의 새 `review.derived` 키에
  정본→사본 경로 프리픽스 매핑을 선언하면, 현재 바이트가 정본과 동일한 사본은 크기 계상에서
  빠지고 critical 을 강제하지 못합니다 — 정본의 분류가 결정합니다. 드리프트난 사본은 그대로
  계상됩니다(동일성은 이미터가 티어 계산 시점에 직접 검증하며, 심볼릭 링크는 어느 쪽이든
  면제 불가; 상시 게이트가 동일성을 검사하는 쌍은 플러그인 소스↔템플릿뿐 — ADR 0037 후속
  참조). 면제·억제는 티어 라인에 항상 명시됩니다. 순수 전파 diff(사본만 갱신)는 counted 0으로
  small — skip 으로는 절대 내려가지 않습니다. `derived` 를 선언하지 않은 레포는 출력이 바이트
  단위로 동일합니다.
- **선언 파일 criticality 를 변경 키에서 계산** (ADR 0038): `.harness.json` 이 diff 에 있으면
  변경된 최상위 키를 계산해(주석 키 재귀 제거), {docs, handoff, artifacts}·주석에 국한된
  변경은 critical 을 강제하지 않습니다. 그 외 키(groups, verify, review, retro)는 선언 여부와
  무관하게 모든 레포에서 critical — 선언이 스스로를 옵트아웃할 수 없습니다. 기준을 알 수 없는
  경우(새로 추가된 선언, 파싱 불가)도 critical 입니다.
- 스캐폴드 템플릿 `harness.json` 에 `derived` 키를 문서화했습니다(기본 빈 목록 = 면제 비활성).
  (참고: CHANGELOG.md 를 docs_only 로 분류하는 변경도 이 슬라이스에 있었으나, 적대 리뷰가
  버전 안내 훅(ADR 0030)이 이 파일의 불릿을 모든 멤버 세션 시작에 렌더링함을 확인해 같은
  슬라이스에서 철회했습니다 — 릴리스 노트는 세션에 도달하는 산문이므로 리뷰 면제가 아닙니다.)

## v0.23.2 — 2026-08-06

- 게이트 스크립트의 **저심각도 하드닝 3건** (2026-07-29 리뷰에서 큐잉된 후속 조치): ① 토큰
  검증 정규식의 앵커를 `$` → `\Z`로 교체 — 파이썬의 `$`는 끝 개행 앞에서도 매칭되므로, 호출부
  전처리에 기대지 않고 검증기 자체가 개행 꼬리를 거부합니다. ② 명령 조립 단계의 cwd 2차
  거부가 이제 경고를 남깁니다(이전엔 조용히 `cd`만 생략). ③ 스크립트 게이트 선언의 모르는
  키(`"args"` 등)는 경고와 함께 무시되고, `"files"`에 불리언 아닌 값(문자열 `"false"` 등)이
  오면 참으로 강제되지 않고 경고 후 false(전체 프로그램)로 처리됩니다.
- 게이트 이미터의 **문구 정확화 2건**: 게이트가 하나도 안 나왔을 때의 안내가 "선언된 게이트가
  전부 거부/스킵됨" 원인도 명시합니다. 인자로 못 넘기는 파일명이 있어도 그룹에 전체 프로그램
  게이트가 있으면 "UNGATED"라고 과장하지 않고 파일 단위 커버리지 손실만 정확히 보고합니다.
- 동작 변경은 ③의 비불리언 `files` 처리 하나를 제외하면 경고·문구 추가뿐입니다. 예외를 정확히
  말하면: `"files"`에 문자열 `"true"` 같은 참-강제 값을 선언했던 레포는 이전엔 (우연히) 파일
  스코프 게이트로 동작했고, 이번부터는 경고와 함께 전체 프로그램 게이트로 동작합니다 — 불리언
  `true`/`false`를 선언한 레포는 영향 없습니다.

## v0.23.1 — 2026-08-06

- 스캐폴드 배치의 **줄끝 결함 수정** (ADR 0036): 플러그인 캐시가 CRLF로 체크아웃되는 머신
  (git `core.autocrlf`)에서 `/ywr-harness:harness-init` 가 템플릿의 CRLF 바이트를 그대로
  복사했습니다 — eol=lf 레포에서는 재실행 때마다 가짜 수정 파일이 보이고, POSIX 클론에서는
  배치된 git 훅이 `/bin/sh^M: bad interpreter` 로 죽는 결함. 이제 배치가 줄끝을 소유합니다:
  쓸 때 CRLF 는 LF 로 접히고(쌍만 — 단독 0x0D 는 내용으로 보존), 줄끝만 다른 파일은 변경으로
  세지 않습니다(리프레시 안내 훅과 같은 비교 계약, ADR 0033). 동작 변경은 이것뿐이며, 시드
  보존·거부 규칙은 그대로입니다.

## v0.21.0 — 2026-08-06

  툴체인(벤더 게이트 스크립트 · CI 워크플로 · git 훅 · docs 빌더)이 설치된 플러그인의

  아무것도 바꾸지 않고, 차이가 없으면 침묵합니다.
- 시드(`CLAUDE.md` · `.harness.json` 등 레포 소유 파일)와 마커 없는 `post-commit`(레포
  자체 훅)은 비교하지 않습니다 — 스캐폴드가 덮어쓰지 않는 파일은 안내 대상도 아닙니다.
  줄끝(CRLF/LF)만 다른 파일은 같은 것으로 취급합니다. 자동 훅은 6종이 됩니다.
