## v0.23.1 — 2026-08-06

- 스캐폴드 배치의 **줄끝 결함 수정** (ADR 0036): 플러그인 캐시가 CRLF로 체크아웃되는 머신
  (git `core.autocrlf`)에서 `/ywr-harness:harness-init` 가 템플릿의 CRLF 바이트를 그대로
  복사했습니다 — eol=lf 레포에서는 재실행 때마다 가짜 수정 파일이 보이고, POSIX 클론에서는
  배치된 git 훅이 `/bin/sh^M: bad interpreter` 로 죽는 결함. 이제 배치가 줄끝을 소유합니다:
  쓸 때 CRLF 는 LF 로 접히고(쌍만 — 단독 0x0D 는 내용으로 보존), 줄끝만 다른 파일은 변경으로
  세지 않습니다(리프레시 안내 훅과 같은 비교 계약, ADR 0033). 동작 변경은 이것뿐이며, 시드
  보존·거부 규칙은 그대로입니다.

## v0.23.0 — 2026-08-06

- 리뷰 티어의 **크기 측정이 클래스 가중**으로 바뀌었습니다 (ADR 0035): `.harness.json`에
  `docs_only`로 선언된 문서 표면(실행 의미가 없다고 이미 선언된 파일)은 small/full 크기
  임계값 계산에서 제외됩니다. 작은 기능 변경에 ADR·재생성 인덱스·README가 따라붙는 흔한
  슬라이스가 문서 파일 수 때문에 full 리뷰 비용을 내던 문제의 수정입니다.
- **리뷰 범위는 그대로입니다** — 제외는 측정에만 적용되고, 제외가 발생하면 티어 사유
  줄에 몇 개가 제외됐는지 명시됩니다(조용한 축소 없음). critical 표면 우선, 전부 문서면
  skip, `docs_only` 미선언 레포의 출력은 바이트 단위로 동일합니다.

## v0.22.0 — 2026-08-06

- **지금 당장 업데이트** 명령이 생겼습니다: `/ywr-harness:update` 는 백그라운드 자동업데이트
  (다음 세션 시작 시 반영)를 기다리는 대신, 마켓플레이스 카탈로그 갱신과 플러그인 업데이트를
  즉시 실행하고 디스크 버전 변화(이전 → 새 버전)를 보고합니다.
- 자동화할 수 없는 두 단계는 매번 순서대로 안내합니다: ① `/reload-plugins` 입력(또는 재시작)
  — 실행 중인 세션은 시작 시 로드한 버전을 유지하므로 필수, ② 다음 세션 시작 시 스캐폴드
  안내(ADR 0033)가 드리프트를 알릴 **때만** `/ywr-harness:harness-init` 를 레포당 1회 실행.
  스캐폴드 리프레시를 자동 실행하지는 않습니다 — 설치된 플러그인보다 의도적으로 새로운 작업
  트리를 구버전으로 되돌릴 수 있기 때문입니다 (ADR 0034).

## v0.21.0 — 2026-08-06

- 세션 시작 시 **스캐폴드 리프레시 안내**가 생겼습니다: `/ywr-harness:harness-init`로 깔린
  툴체인(벤더 게이트 스크립트 · CI 워크플로 · git 훅 · docs 빌더)이 설치된 플러그인의
  템플릿과 다르면 — 즉 플러그인 업데이트의 개선이 이 레포에 아직 반영되지 않았거나 배치
  파일이 손으로 수정됐으면 — 다른 파일 수와 목록, 리프레시 명령 한 줄을 제안합니다
  (ADR 0033). 리프레시는 **레포당 1회**(한 사람이 실행해 커밋)면 됩니다. **제안만** 하며
  아무것도 바꾸지 않고, 차이가 없으면 침묵합니다.
- 시드(`CLAUDE.md` · `.harness.json` 등 레포 소유 파일)와 마커 없는 `post-commit`(레포
  자체 훅)은 비교하지 않습니다 — 스캐폴드가 덮어쓰지 않는 파일은 안내 대상도 아닙니다.
  줄끝(CRLF/LF)만 다른 파일은 같은 것으로 취급합니다. 자동 훅은 6종이 됩니다.

## v0.20.0 — 2026-08-05

- 레포가 발행한 claude.ai 아티팩트를 `.harness.json`의 `artifacts` 섹션에 선언하면, 하네스
  게이트가 **README에 그 링크가 있는지**와 **선언된 제목이 레포 이름으로 시작하는지**
  (`<레포명> · <용도>` 규칙)를 검사하고, 위반 시 CI가 실패합니다 (ADR 0032).
- 선언하지 않은 레포는 이전과 동일하게 동작합니다 — 검사가 꺼져 있다는 사실만 게이트
  출력에 한 줄로 보고됩니다.
- 선언된 `url`/`title` 에 제어문자(줄바꿈 등)가 있으면 위반으로 보고합니다. 나아가 게이트
  emitter 와 `/ywr-harness:verify` 매퍼의 **모든 출력 줄이 한 곳을 통과**하도록 바뀌어, `.harness.json` 의
  값·그룹 이름·파일명 등 레포가 제공한 어떤 텍스트도 출력 줄을 새로 만들 수 없습니다 — 그런
  줄이 만들어지면 CI 와 pre-commit 이 그것을 게이트 명령으로 착각해 실행할 수 있었습니다.
  경고(stderr) 줄도 같은 처리를 받습니다: 커밋 중 터미널에 ESC 시퀀스가 그대로 나가면 훅의
  출력을 덮어쓸 수 있기 때문입니다.
